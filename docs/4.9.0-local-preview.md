# agy-switch 4.9.0 local Mac preview

On 2026-10-05, the owner requested an installed local preview of source commit `74395e96` on `codex/cli-policy-workflows`. This is a local development build; it does not publish a GitHub release or change the public 4.8.1 assets.

## Build and installation

- Built the optimized Apple Silicon app with the locked Cargo dependencies and ad hoc signing:

  ```sh
  APPLE_SIGNING_IDENTITY='-' CXXFLAGS='-isystem /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/c++/v1' npm run tauri build -- --target aarch64-apple-darwin --bundles app -- --locked
  ```

- Installed the complete bundle at `~/Applications/agy-switch.app`. The Desktop entry `~/Desktop/agy-switch.app` points to that bundle.
- Desktop FileProvider adds Finder metadata to copied bundles, causing strict code-signature verification to fail. The installed bundle uses the local Applications directory and passes the same verification without relaxing it. No quarantine or security attributes were removed.
- Preserved both an original copy and the retired Desktop bundle under the ignored `artifacts/mac-review/` directory. The existing `/Applications/Antigravity Tools Lite.app` installation was not replaced.
- Kept the bundle identifier and account/configuration data paths. No account migration or preference reset was performed.

## Verified result

- The installed bundle reports version **4.9.0**, architecture **arm64**, verified code-signature integrity, and empty entitlements. This is not Developer ID or notarization acceptance; Gatekeeper and notarization were not tested.
- Both executables in the actual release bundle passed **27 CLI smoke checks each**, using isolated synthetic data.
- Quit the previous desktop process and launched the installed bundle through native app controls. The running executable is `~/Applications/agy-switch.app/Contents/MacOS/agy-switch-desktop`; no previous desktop executable remained running.
- Native accessibility and screenshots confirm the window title and navigation branding are **agy-switch**, with the new blue/mint icon.
- The installed smart-switch settings visibly separate **切换时机** from **账号选择顺序**. Existing accounts and policy selections remain available. Verification did not change policy preferences or switch real accounts.

Build logs and app backups remain local in the ignored review directory. This preview does not verify Windows/Linux installation or publish installers.

## Terminal entry follow-up

The first local preview updated the app but missed the shell entry points. `~/.local/bin/agy-switch` still pointed to the retired Desktop bundle, while `/opt/homebrew/bin/agy-switch` pointed to the Homebrew 4.8.0 app. Both symbolic links now point to `~/Applications/agy-switch.app/Contents/MacOS/agy-switch`; their previous targets are retained in the ignored review directory. The Homebrew app bundle and Google's `agy` executable were not replaced. A later Homebrew cask installation may reset its managed command link.

Both command paths report **agy-switch 4.9.0**. The terminal menu exposes **6. 策略与排序** and **7. 检查更新**. The policy editor separates switch timing from account selection order and includes candidate selection/sorting. The desktop app remains the background policy executor. An already-running old terminal process must be exited and restarted to use the new executable.

The repaired user-local command passed **51 real PTY checks** covering Chinese/English policy menus, candidate ordering, saving, cancellation and keyboard interaction with isolated synthetic data.
