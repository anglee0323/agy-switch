## 本次修复

- 修复自动切换写入客户端数据库失败时仍报告成功的问题。备份或写入失败会暂停后续切换、保留当前账号记录，并显示失败；部分写入后不会继续重启客户端。
- 提高 OAuth 本地回调的稳定性：无效首连、空连接和分段请求不会提前结束授权；回调有大小、并发和等待时间限制，支持取消并校验状态。日志不再记录令牌前缀或回调原文。
- 修复损坏的客户端数据触发 protobuf 越界或整数溢出的问题。修正 CLI 刷新入口提示、未安装 App 时的切换检查，以及多账号列表在较小终端中的重绘和选中行显示。
- Windows 切换会等待客户端退出并在超时范围内重试。统一 Windows 程序和测试所需的系统控件清单，更新依赖并对齐 Tauri 前后端工具版本。

## Changes

- Stop reporting successful automatic switches when client database backup or credential injection fails. Pause further attempts, retain the selected-account record and surface the failure; do not restart clients after a partial write.
- Make local OAuth callbacks tolerate invalid first connections, empty connections and fragmented headers. Bound request size, concurrency and waiting, support cancellation and validate state. Remove token prefixes and raw callback requests from logs.
- Reject malformed protobuf lengths and overflowing integers instead of crashing. Correct the CLI refresh shortcut, enforce the missing-App switch check, and keep large account lists and their selection visible in small terminals.
- Wait for Windows clients to exit and retry within the timeout. Share the required Windows controls manifest across application and test executables, update dependencies and align the Tauri JavaScript/native toolchain.

Addresses issues #96–#103 through PR #110, integrating the earlier repair PRs.

## Verification and limits

Regression coverage includes malformed and overflowing protobuf data, failed
database backup/injection, invalid and fragmented real localhost callbacks,
authorization cancellation/expiry, missing-client checks, Windows exit deadlines
and both account pickers with 40 synthetic accounts in real PTY/ConPTY terminals.
Three-platform source checks, optimized CLI checks and complete candidate package
validation passed for the integrated fixes. The versioned source must pass its
own checks before publication.

Account tests use isolated synthetic storage. They do not switch, refresh, export
or delete saved real credentials, or interrupt running client tasks. Hosted native
WebView checks do not establish real Google login, authenticated switching or
physical Windows/Linux tray behavior. A selected-account record alone does not
prove the client's live identity. See [account scopes](../account-scopes.md).

The npm audit was clean for the integrated dependency updates. Some transitive
Cargo advisories remain constrained by upstream dependencies; this release does
not claim that all native dependency advisories are resolved. Tailwind remains
on version 3 with an updated selector parser; no Tailwind 4 migration is included.

Mac packages lack Developer ID/notarization and Windows packages lack Authenticode.
Integrity and updater signatures do not establish OS trust. Installation requires
user action; see [updates](../software-updates.md).
