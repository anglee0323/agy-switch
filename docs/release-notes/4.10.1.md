## 本次更新

- “设置 → 实验功能”只保留二级页面中的“界面汉化”开关。移除懒人配置、单项客户端设置和权限规则 JSON 编辑；此前修改的 Antigravity 设置会保留，不会自动恢复默认值。
- 汉化接入 Windows 和 macOS 的独立 Antigravity App，覆盖侧边栏、设置和内置嵌套页面中的已知界面文字。Antigravity IDE、agy CLI、VS Code 和 JetBrains 插件不受影响；聊天、代码、用户输入、插件正文和系统菜单保持原文。
- CLI 主菜单新增“实验功能 → 界面汉化”，与桌面共用开关。也可使用 `agy-switch experiments show`、`translation on|off` 和 `run`。仅用 CLI 时，开启后保持 `agy-switch experiments run` 在前台运行；Ctrl+C 停止该进程的续期。
- 补充运行时注入说明：通过 App 现有本机连接替换已知界面标签，不修改安装文件或源文件，不调整权限或账号设置，也不上传聊天内容。关闭后恢复原文；没有其他 Switch 进程续期时，最后一次续期的 15 秒租期到期后恢复。注入脚本仍在 App 页面中运行，不能承诺完全没有风险。

## Changes

- Settings → Experimental Features now contains only the secondary Chinese interface switch. Removes quick setup, individual client preferences and permission-rule JSON editing. Existing Antigravity preferences are retained rather than reset.
- Connects translation to the standalone Antigravity App on Windows and macOS, covering known built-in sidebar, settings and nested-page labels. Antigravity IDE, agy CLI, VS Code and JetBrains plugins are unaffected. Conversation/code bodies, user input, plugin contents and OS menus retain their original text.
- Adds Experimental Features → Chinese interface to the CLI main menu, sharing the desktop switch. Commands are `agy-switch experiments show`, `translation on|off` and `run`. For CLI-only use, keep `agy-switch experiments run` in the foreground after enabling translation; Ctrl+C stops that runner's renewals.
- Explains runtime injection through the App's existing local connection. It does not modify installation/source files, permissions or accounts, or upload conversations. Turning it off restores text; without another Switch process renewing it, the last 15-second lease restores text when it expires. The injected script still executes inside App pages and is not risk-free.

## Verification and compatibility

Live macOS acceptance covered standalone Antigravity Apps 2.21.1 and 2.22.0. App 2.22.0 translation/restoration used isolated Switch storage; installed Switch desktop/CLI coexistence observed 23 translated labels. The saved GUI and translation preferences remained unchanged during the latest local App/CLI replacement. No real account switch or permission-policy mutation was used.

Source checks covered desktop/CLI hierarchy and saved-switch behavior, dynamic and alternate sidebar layouts, content exclusion, restoration, process/package/listener ownership and foreground cancellation. Local builds passed frontend production compilation, locked Rust checks, browser tests, CLI executable checks and real macOS PTY interaction. The final versioned source must pass macOS, Windows and Linux CI before tagging; all three package jobs, packaged installer/CLI checks, complete asset hashes and signed updater verification are required before publication.

Windows native App discovery follows the official 2.21.1 package layout and verifies current-user executable ownership, its parent language server and complete TCP listener ownership. Windows API/build and hosted Switch window checks are separate from signed-in Antigravity App acceptance; a live Windows App session has not been tested locally. Windows WSL, Linux App translation and Antigravity IDE are unavailable. Older sidebar layouts have synthetic coverage rather than native acceptance for every version; unknown labels retain their original text.

Desktop or a foreground CLI runner must remain active for translation. Multiple Switch processes can renew the same App controller, so stopping one runner does not establish isolated expiry while another remains active. The 15-second lease has browser coverage; isolated live lease expiry was not established in that coexistence environment. Translation excludes third-party embedded pages and user content, and unsupported or unverifiable connections remain unavailable.

Mac 2.21.1 和 2.22.0 已做实际 App 验证；Windows 原生适配已做 API、构建和 Switch 窗口检查，本机尚未实测登录后的 Windows Antigravity App。Windows WSL、Linux App 汉化和 IDE 不支持；旧版侧边栏只有模拟布局覆盖。多个 Switch 进程可共同续期，停止一个进程不会让其他进程维持的汉化立即失效；15 秒到期恢复有浏览器测试，但该共存环境未完成隔离的实际 App 到期验证。

Packages have no Apple Developer ID/notarization or Windows Authenticode certificate. Ad-hoc bundle integrity and updater signatures do not establish OS trust. Installation requires user action, and Homebrew does not bypass trust checks.
