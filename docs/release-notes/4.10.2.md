## 本次更新

- 修复“确认任务空闲后切换”停在等待状态的问题。即使由 Claude/GPT 的低额度触发，也会等待 Gemini 等全部 App 对话和后台执行器空闲，再自动关闭相关客户端、切号并重新打开。
- macOS 下，已验证的 App 数据 Hub 不再仅因常驻 `agy` 进程而阻止切换。关闭前重新检查其任务状态，切号后恢复此前运行的 Hub；启动参数只在内存中保留，不写入日志。
- 关闭客户端前保存重启计划，并在临时进程检查失败时保留。设置、菜单栏和 CLI 状态区分等待任务、自动关闭、关闭失败和换号后重启失败，避免笼统要求用户手动关 App。
- 修复 Claude Opus 4.6 等已知模型的 `-thinking` 名称匹配，桌面、菜单栏和 CLI 使用一致的官方价格估算。简化费用卡片说明，将圆环中的“已计价小计”改为“预估费用”；无法匹配的价格仍不计入估算。
- 双模型系列额度显示中，每个账号保留主名称，副名称位置改为 Gemini 与 Claude/GPT 分组标题；两组分别显示“5 小时”和“每周”，增加间距与分隔线。单系列显示保留邮箱/备注副名称。

## Changes

- Fixes wait mode remaining pending after App conversations finish. A Claude/GPT quota trigger still waits for all App conversations and background executors, including Gemini, before automatically closing affected clients, switching accounts and reopening them.
- On macOS, a verified App-data Hub no longer blocks switching solely because its persistent `agy` process exists. Its activity is rechecked before closing; a previously running Hub is restored after switching. Launch arguments remain in memory and are excluded from logs.
- Captures the relaunch plan before client shutdown and preserves it through temporary process-observation failures. Settings, menu and CLI status distinguish waiting, automatic closing, close failure and relaunch failure after a successful account change.
- Matches known Claude `-thinking` aliases, including Opus 4.6, consistently across desktop, menu and CLI estimates. Simplifies the cost card and labels the ring “Estimated cost.” Unknown model prices remain excluded.
- In the two-family quota layout, each account retains its primary identity and uses its secondary line for Gemini and Claude/GPT group labels. Both groups repeat the five-hour and weekly labels, with spacing and a divider. Single-family mode retains the secondary email/remark.

## Verification and compatibility

The production coordinator was tested with isolated synthetic accounts: Claude below the reserve while Gemini remains busy, all conversations becoming idle, automatic close, credential commit and App/Hub relaunch. Regression checks cover transient unknown process state, relaunch failure, cancellation, source identity and commit guards. macOS read-only observation of Antigravity App 2.22.0 confirmed an idle App-data Hub and preserved Busy for an ongoing App task. No real account switch or shutdown of active Antigravity work was used for acceptance.

Frontend, Rust, mocked browser UI, ARM64 source-bundle integrity, console smoke and real macOS PTY checks passed for the fixes. The final versioned source must pass macOS, Windows and Linux checks before tagging. Publication requires all three package jobs, packaged installer/CLI tests, complete-set hashes and signed updater verification. Mocked UI and synthetic credential boundaries do not establish authenticated account switching or physical tray acceptance.

Live wait-mode task confirmation supports the macOS standalone App and the verified native `agy --hub --app_data_dir antigravity` server. Interactive CLI sessions, other Hub data roots, extra IDE/language-server processes, Windows/Linux and unavailable state remain unknown and keep wait mode pending. New work can begin after an idle observation; this is not an atomic execution lock. Running work is not migrated or automatically continued on the new account. App translation remains limited to standalone Windows/macOS App.
