## 本次更新

- 移除账号页的 App/CLI 与 IDE 切换下拉框，直接切号继续同步 Antigravity App 和已初始化的原生 agy CLI。保留后台的客户端隔离与切换保护；CLI 和自动切换策略仍可明确指定 IDE。
- 账号多选复用仪表盘的小蓝勾方框，支持键盘操作和部分选中状态。批量导出使用绿色按钮，单个和批量导出都放在操作区最后。
- 保留 4.10.3 的系统代理跟随、账号导出与文件恢复、本地导入漏账号修复。

## Changes

- Removes the App/CLI versus IDE selector from the account page. Direct switching continues to synchronize Antigravity App and an initialized native agy CLI session. Client isolation and switching safeguards remain; CLI commands and scheduler policies can still explicitly target IDE.
- Account selection uses the Dashboard's small blue square checkbox, with keyboard access and partial-selection state. Batch export has a green button, and single-account and batch export appear last in their action groups.
- Retains the system-proxy routing, account export/file restoration and local-import discovery fixes from 4.10.3.

## Verification and limits

The feature PR passed all three platform Build jobs and both optimized release-CLI jobs. Local frontend compilation, nine focused bilingual account/layout/transfer/network UI cases and 42 CLI checks passed. A locally built ARM64 App passed strict bundle-resource and signature checks; its installed native account page was visually reviewed without switching, refreshing, exporting or importing real accounts.

These UI checks use synthetic accounts and mocked service responses. They do not establish live Google authorization or authenticated App/CLI/IDE switching. The release process separately validates candidate packages, actual Windows/Linux installations and terminal behavior before publication. Native Homebrew installation, upgrade and uninstall acceptance remain separate tasks.

App/CLI share credentials; a running agy command may keep its previous session until restarted. Saved selections are local records rather than proof of live identity. Fixed system proxies and proxy environment variables are supported; PAC evaluation and automatic proxy discovery remain unsupported.

本次没有操作维护者的真实账号。代理、导入、导出与后台客户端隔离代码保留，账号页直接切号默认同步 App/CLI；真实登录和各用户网络环境仍需单独验收。

Mac packages have no Apple Developer ID/notarization, and Windows packages have no Authenticode certificate. Complete ad-hoc bundle integrity and updater signatures do not establish OS trust. Installation requires user action; Homebrew does not bypass trust checks.
