## 本次修复

- 修复 4.10.9 的账号额度窗口显示：选择 5H 时，模型行和重置时间排序使用五小时窗口，不再显示较低的周额度和数天后的周重置时间。周配额页继续显示自己的额度和重置时间。
- 兼容已缓存的周额度融合结果；五小时数据缺失或冲突时保持未知，不借用周数据。保留原始模型观测，避免共享五小时摘要抬高模型自身更低的额度。
- Gemini 4 Argon 继续使用独立周额度，在模型行中明确标为“周配额”。自动切换与 CLI 的有效额度仍同时受五小时和周窗口限制。

## Changes

- Fix account quota windows after 4.10.9: the 5H view and reset-time sorting use the five-hour observation instead of a tighter weekly value and a multi-day reset. The weekly view retains its own allowance and reset.
- Handle already-fused weekly caches. Missing or conflicting five-hour data stays unknown instead of borrowing the week. Preserve original model observations so a shared five-hour summary cannot increase a lower model allowance.
- Keep Gemini 4 Argon on its independent weekly pool and label it Weekly in model rows. Automatic switching and CLI effective quotas remain bounded by both five-hour and weekly limits.

Addresses issue #87 through PR #88.

## Verification and limits

Regression coverage includes the original cached Gemini failure, Chinese/English
card and table views, window switching, reset sorting, unknown/conflicting data,
independent Argon labels and preserved primary observations. Local tests use
synthetic data; they do not switch or refresh saved real accounts. Three-platform
source and package checks are required before publication.

This update corrects window presentation. A displayed five-hour allowance does
not override an exhausted week or grant model access. Upstream omissions remain
unknown. See [quota data sources](../quota-pools.md).

Integrity and updater signatures do not establish OS trust. Installation requires
