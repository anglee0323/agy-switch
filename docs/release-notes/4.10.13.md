## 本次更新

- 账号列表分页或搜索后拖拽排序，不再把当前页的账号整体挤到整个列表最前面：可见账号沿用各自原来的位置，其他账号保持不动，保存的是完整顺序。
- 命令行新增 `agy-switch switch ACCOUNT --target agy`：切换 App 与 `agy` 共用的登录，但不关闭、不启动、不重启 App、IDE 或任何其他进程。之后新的 `agy` 命令立即使用新账号；正在运行的 App 继续使用已加载的账号，直到它重启。适合脚本和智能体在额度用尽时自动换号。
- 修复一个误判：AntiGravity Switch 自己的进程（`agy-switch-desktop`、`agy-switch`）路径含 “antigravity”，曾被当成 Antigravity App。只开着 Switch 窗口时用命令行切号，会关闭该窗口并启动真正的 App；现在 Switch 自己的进程不再被识别为 App。

## Changes

- Reordering accounts after pagination or a search no longer moves the visible accounts to the front of the whole list. They keep the positions they held, every other account stays where it was, and the complete order is saved.
- Add `agy-switch switch ACCOUNT --target agy` to the CLI. It switches the login shared by the App and `agy` without closing, starting or restarting the App, the IDE or any other process. New `agy` commands use the new account at once; a running App keeps the account it loaded until it restarts. Scripts and agents can use it to move to another account when quota runs out.
- Fix a false match: AntiGravity Switch's own processes (`agy-switch-desktop`, `agy-switch`) have paths containing "antigravity" and were taken for the Antigravity App. A CLI switch with only the Switch window open closed that window and launched the real App. Switch's own processes are no longer recognized as the App.

## Verification and limits

`--target agy` was verified once on a Mac with real saved accounts and the App open: the App process kept its PID and start time, a new `agy` run authenticated as the new account and still did 60 seconds later, a relay job moved from one account to another in the same conversation, and the original account was restored. Automated checks cover only the paths that fail before any credential write, because a real switch writes the system credential store. Windows and Linux use the existing credential write for this target but it was not tested there. Whether a running App later writes its own session back was not observed beyond that minute. See [CLI guide](../cli.md).

The pagination fix has three new mocked-UI checks (page 2, search result, rejected save). The two unit tests for the false match cover the Switch and App paths of all three platforms; the original false match was not reproduced end to end because that would close a real Switch window.

Rust (234) and CLI smoke (45) and PTY (68) checks, the mocked UI suite and the three package jobs passed in CI. The real-account switches above were limited to switching and restoring the logins; no account was refreshed, exported or deleted.
