## 本次更新

- 适配 Antigravity IDE 2.6 统一登录：IDE 2.6 及以上改由内置扩展启动与 App 相同的后台服务，并使用 App 与 `agy` 共用的登录，不再从自身数据库读取账号。检测到这类 IDE 时，切换 App/CLI 与切换 IDE 变为同一操作：写入共用登录，关闭并重新打开正在运行的 App 和 IDE，同时记为两者的当前账号。IDE 自己启动的后台服务不会被 Switch 以旧参数重新拉起，重新打开的 IDE 会自行启动新的服务。自动切换中目标为 IDE 的策略也改为校验和写入共用登录。2.6 以下或无法识别版本的 IDE 保持原来的独立切换。
- Windows 关闭 Antigravity 改为先请求窗口正常关闭，以便客户端保存状态；在大部分关闭等待时间内仍未退出（例如在后台或托盘运行、没有可见窗口或停在确认框）时，才强制结束剩余进程，与 macOS、Linux 的处理一致。
- Windows 切换 App 账号前，如果默认 App 状态文件 `%USERPROFILE%\.gemini\antigravity\antigravity_state.pbtxt` 非空、不超过 16 MiB 且内容全为零字节，会在客户端关闭后将其原样改名备份，让 Antigravity 下次启动时重新生成。仍有 Antigravity、`agy.exe` 或 `language_server.exe` 在运行、文件被占用或备份失败时，切换会在写入凭据前停止。其他损坏形式和自定义位置不处理。

## Changes

- Support the Antigravity IDE 2.6 unified sign-in. IDE 2.6 and later start the same background Hub as the App through the built-in extension and use the login shared by the App and `agy`; the account no longer comes from the IDE databases. When such an IDE is detected, App/CLI and IDE switching are one operation: the shared login is written, a running App and IDE are closed and reopened, and the account is recorded for both. Switch does not relaunch the IDE's own Hub with its old arguments; the reopened IDE starts a new one. Automatic-switching policies that target the IDE verify and write the shared login. IDE versions before 2.6, or an unrecognized version, keep independent switching.
- On Windows, Antigravity is first asked to close its windows normally so it can save its state. Remaining processes are force-closed only if it is still running after most of the close timeout (for example, when it runs in the background or tray, has no visible window or waits on a confirmation), as on macOS and Linux.
- Before a Windows App account switch, a default App state file `%USERPROFILE%\.gemini\antigravity\antigravity_state.pbtxt` that is nonempty, at most 16 MiB and entirely zero bytes is renamed to a backup after the client closes, so Antigravity recreates it on the next launch. If Antigravity, `agy.exe` or `language_server.exe` is still running, the file is locked or the backup fails, switching stops before credentials are written. Other corruption and custom locations are not repaired.

## Verification and limits

The IDE 2.6 behavior is based on the official authentication documentation and the IDE 2.6.0 changelog, plus inspection of the public IDE 2.6.0 package: its built-in extension installs `~/.gemini/bin/agy` and starts it as `agy --hub --app_data_dir=antigravity`. Unit tests cover the 2.6.0 version boundary, `ideVersion` discovery for the macOS bundle, Windows/Linux layouts and a Linux `bin/` launcher, and recognition of IDE-owned Hubs. No live switch with an installed IDE 2.6 was performed, and Windows/Linux IDE behavior is untested. Whether an IDE Hub can outlive its IDE was not observed.

The Windows changes were checked in Windows CI. Recovery tests used synthetic files: all-zero preservation, ordinary/mixed/empty files, an active-writer guard, a locked file, an oversized file and refusal to overwrite a backup. A signed-in Windows switch, tray-only shutdown and the cause of the observed zero-filled file were not tested.

Rust tests (238 on macOS), the mocked UI suite and the three package jobs passed in CI. No real account was switched, refreshed, exported or deleted for these checks.

Mac packages lack Developer ID/notarization and Windows packages lack Authenticode.
Integrity and updater signatures do not establish OS trust. Installation requires
user action; see [updates](../software-updates.md).
