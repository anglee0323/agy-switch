## 本次更新

- Gemini 4 Argon 配额在接口返回时按独立周额度展示，保留重置时间。账号卡片、表格、首页、菜单栏／托盘和 CLI 不再把它混入普通 Gemini 共享池。
- 修复配额分组顺序导致的模型关联错误，以及 CLI 中 Argon 覆盖普通 Gemini 数据的问题。缺失、无效或冲突的额度保持未知，不再显示旧百分比。
- 配额摘要优先查询生产接口，避免 Sandbox／Daily 返回 HTTP 200 但缺少 Gemini 分组时直接采用不完整结果。
- 显式监控 Argon 模型时使用其独立周额度；`gemini` 策略继续监控普通 Gemini 共享池。补齐中英文显示和窄托盘窗口布局。

## Changes

- Show a reported Gemini 4 Argon pool as an independent weekly allowance with its reset time. Account cards/tables, Dashboard, menu bar/tray and CLI keep it separate from shared Gemini quota.
- Fix model association depending on group order and Argon replacing shared Gemini figures in the CLI. Missing, invalid or conflicting observations remain unknown instead of exposing an old model percentage.
- Query the production quota-summary endpoint first. Sandbox/daily can return HTTP 200 while omitting the Gemini group.
- Explicit Argon model monitoring uses its dedicated weekly pool; the `gemini` policy scope continues to monitor shared Gemini. Include bilingual labels and compact tray layouts.

## Verification and limits

Argon support applies when the account's quota source actually reports the pool.
Read-only probes of the available Pro accounts and Antigravity App 2.24.0 returned
the shared pools but no Argon pool. The independent-pool behavior is covered by
synthetic observations; this release does not establish live Argon availability
for every eligible Pro, Ultra or enterprise account. A local App quota RPC is not
a multi-account data source. See [quota pools and data-source limits](../quota-pools.md).

Release acceptance covers the final source/version, three-platform builds,
backend/frontend regressions, isolated CLI and real terminal checks, and actual
Windows/Linux package installation checks. Native GUI reports and downloaded
public-package verification are recorded separately in the maintainer acceptance
notes. Synthetic checks do not prove authenticated switching or physical tray
behavior on every system. No real account switching or credential refresh is
needed for package acceptance. Native Homebrew install/upgrade/uninstall remains
a separate verification scope.

Mac 安装包没有 Developer ID 签名或公证，Windows 安装包没有 Authenticode 证书。
完整资源签名和更新签名不能替代操作系统信任；安装仍需用户操作。

Mac packages have no Apple Developer ID/notarization; Windows packages have no
Authenticode certificate. Bundle integrity and updater signatures do not establish
OS trust. See [updates](../software-updates.md), [Homebrew](../homebrew.md) and the
[release checklist](../maintainers/release-checklist.md).
