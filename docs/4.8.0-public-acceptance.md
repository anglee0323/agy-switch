# 4.8.0 public-package acceptance

Published [v4.8.0](https://github.com/anglee0323/agy-switch/releases/tag/v4.8.0) is built from main commit `4c01890722aef8a115cacd93857eb6cabeb92bd7`. The [tagged release run](https://github.com/anglee0323/agy-switch/actions/runs/37243362570) passed all three package jobs and complete-asset validation. The first publisher attempt created an empty draft but stopped with `Could not confirm the draft release` when the release listing did not immediately return it. The existing draft matched the tagged source and reviewed notes; retrying only failed jobs published the same previously verified packages. No public asset or tag was overwritten. Source-document links in the public notes were subsequently resolved to full URLs at that source commit.

## Public downloads

All twelve attachments were downloaded. Their bytes match GitHub asset digests, the SHA-256 files and the source manifest. The five payloads are the Mac ARM64 ZIP, Windows x64 installer, Linux amd64 deb, Windows console ZIP and Linux console tarball. The other attachments are their five checksum files, generated Homebrew cask and source manifest.

The root cask is byte-for-byte identical to the public attachment. The Mac ZIP SHA-256 is `f77dadc3fb004d8f284a6d4134fb004c68ddf5c9dbde9694c808c53364544f53`. The public Windows CLI has an x64 PE header and console subsystem; the public Linux CLI is an x86-64 ELF executable. These local format checks do not execute those binaries on Mac.

## macOS and Homebrew

- The public ZIP extracted into a fresh OS temporary directory verifies as ARM64, bundle version 4.8.0, a complete strict signature and empty entitlements. It passed all 14 isolated CLI read checks. Its `agy-switch` entry point passed 13 real PTY checks, including navigation, masked input, resize and clean exit, without authorization or account writes.
- Real Homebrew upgrade from 4.7.9 to 4.8.0 succeeded in `/Applications`, using the exact verified cask. The `agy-switch` link resolves to the installed bundle's executable. Twelve existing account/configuration JSON files remained byte-for-byte unchanged; contents and fingerprints are not published.
- The Brew-installed bundle passed strict signature verification and retained its quarantine marker. Gatekeeper returned exit 3, `rejected`; its CLI version invocation timed out after ten seconds with `ETIMEDOUT`. Installation and data preservation passed. Quarantined launch did not pass. No quarantine, OS trust setting or signature was changed to make the test pass.
- Homebrew DSL loading and Ruby syntax checks passed. Earlier custom `--appdir` behavior is recorded separately in [4.7.9 acceptance](release-notes/4.7.9-public-acceptance.md). The normal user development app was not replaced by this Brew upgrade.

## Windows and Linux

The tagged Windows job passed actual release executable reads, direct PowerShell waiting/error-code checks, 13 ConPTY checks, and installation/uninstallation of the NSIS package in its disposable hosted runner. The tagged Linux job passed deb metadata/payload checks, executable reads without a display, 13 PTY checks and actual APT installation/uninstallation in its disposable Ubuntu 22.04 runner. Both jobs packaged their tested console executable as a separate download.

The main-source [Build run](https://github.com/anglee0323/agy-switch/actions/runs/37242220518) and [release CLI run](https://github.com/anglee0323/agy-switch/actions/runs/37242220548) passed. Native GUI reports use synthetic accounts; published screenshot provenance identifies its distinct debug-test source precisely. See [native window acceptance](native-gui-acceptance.md) and [4.8.0 screenshots](screenshots/4.8.0/README.md).

## Remaining boundaries

The Linux console does not initialize a display but still requires GTK3/WebKitGTK runtime libraries. Native viewport tests do not establish installed-package GUI launch, physical tray placement, every Windows 10/11 device, Wayland/KDE behavior, startup registration or real Google authorization/authenticated switching. APP-target switching still requires the actual Antigravity client and credential backend. Mac Developer ID/notarization and Windows Authenticode signing are absent; checksum and build acceptance are not platform-trust acceptance.
