# Quick dashboard and startup preferences

On macOS the overview is an AppKit `NSMenu`, following CodexBar's native menu structure, system typography, fine progress bars and standard action rows. AppKit owns sizing, screen clamping, keyboard tracking and dismissal. The header reads “agy-switch” with the application icon and no duplicate overview subtitle. The menu has three sections: “今日用量” / “Today’s usage”, “剩余额度” / “Remaining quota”, and “账号列表” / “Accounts”. The daily section uses a restrained blue/gold/mint ring chart for input/output/cached token proportions, with matching short legend lines and neutral text, total tokens, request count and an API-equivalent dollar estimate. The redundant USD caption is removed. The aggregate heading is “剩余额度” / “Remaining quota”; its model/mean label is right-aligned. The account section is “账号列表” / “Accounts”, with the account count aligned at the right. The remaining-quota section shows overall quotas with right-aligned available-account counts before remaining percentages. The account section follows the display family selected in Settings; the popup has no family selectors. Each row uses whitespace and a fine separator without a card background or enclosing border, with a primary identity and secondary note and a switch button or read-only status chip fixed on the right, all using the same compact width and height (64×26 in Chinese; 72×26 in English). Titles, account identities and period labels share the left content edge; counts, percentages and action controls share the right edge. Account names retain ordinary foreground text and align with the secondary identity. They are plain read-only labels, with no click target or secondary account page. In the two-family layout, a 12-point gutter separates the first percentage from the second bar without moving the outer content edges. Current uses a blue circle check; disabled uses a red prohibition symbol and label. The account family defaults to both; Settings controls the displayed family. Quota values and optional reset countdowns stay in the account list. Window → Quota Overview (Command–Shift–M) opens the same menu.

Windows/Linux use an opaque WebView panel at 424 × 680 logical pixels, clamped to the work area, with adaptive pagination based on measured row heights. Its hidden window and local usage cache are prewarmed after tray setup; repeated opens reuse the window. The same usage/quota/account sections, identity ordering, normal percentage text and yellow reset labels apply. The system-font stack includes Segoe UI and Noto Sans. Account identities are also read-only labels; coordinator status keeps its separate cancellation/check view. The browser acceptance suite covers this shared panel; it is not evidence of the Mac native menu's appearance.

Click the macOS menu-bar icon or Windows tray icon to toggle it. Linux uses the native tray menu's Quick Dashboard action. Escape, a second tray click and loss of focus dismiss the panel. The main application remains available if the tray cannot initialize.

## Material

The Mac menu uses the system's own menu background, rounding, shadows, semantic foreground colors and accessibility appearance. It has no transparent WebView window or custom glass container. Earlier direct `NSGlassEffectView` root replacement triggered a foreign exception; the background-only attempt was unreadable over bright content. Both were removed. The native menu does not replace any managed window view. Windows/Linux use opaque panel surfaces. Native appearance requires installed-host acceptance, not browser screenshots.

## Quota and identity

General Preferences → Menu bar aggregate quotas selects Gemini, Claude/GPT or all families. The overview defaults to both **5 hours** and **weekly**; either may be hidden, but at least one window must remain. Each is an equal-weight **mean remaining percentage**, not summed tokens or absolute capacity. Shared bucket/window observations are deduplicated. All-family means require both families to be reported for an account. Missing, conflicting, stale, expired, blocked, disabled, forbidden or protected data is excluded. Known low and zero observations stay in the mean; unknown is a dash. The available count uses displayed accounts as denominator and the configured reserve as its cutoff. There is no reported-data coverage tooltip. Availability describes quota headroom; native sign-in is verified during switching.

The menu opens from a read-only, credential-free local snapshot, then checks the running standalone Mac App identity in the background and updates the existing status controls. It does not mark the saved index as a verified live identity while checking. A verified live email supersedes the saved Tools index. Failed, unknown and ambiguous observations do not select the first account. The account heading keeps its count and shows “当前未识别” / “Current unknown” when the live identity cannot be determined; the Mac heading shows a checking state while discovery is pending. The read-only status RPC is not restricted to one client release number; package/process/listener validation and response checks remain required. With the App closed, the saved Tools account is identified as such. The full application and `agy-switch current` retain their documented Tools-record semantics.

While the Mac menu is open, a background reader checks the local account snapshot every second. Quota percentages, bars, reset countdowns and aggregate availability update in place when a scheduled or manual refresh saves new observations; closing and reopening is unnecessary. This reader never requests live quotas or refreshes credentials and stops when the tracking session closes. Account order and layout stay fixed for that session; account additions, removals and visibility changes are reflected on the next open. Failed reads, removed accounts and newly unavailable observations cannot retain usable quota in the aggregate.

Per-row switching uses the existing manual switch backend and can close/reopen the App. Disabled/blocked/unreadable accounts, repeated clicks, active coordinator commits and unreadable coordinator state disable activation. Refresh updates **all** quotas and reports partial failures. Mac operations dismiss the native menu. Successful switching is reflected by the current-account status without a persistent success banner; failures are reported on the next open and then consumed. The Usage Dashboard action opens the existing full application. The daily section reuses the homepage’s local token records and reads the existing official public price cache without a network request on menu open. It displays an in-memory daily snapshot immediately while scanning asynchronously; concurrent menu reads are coalesced, snapshots are refreshed after 30 seconds, and yesterday’s cache is never reused after midnight. App startup warms this cache and homepage scans update it. Rates match normalized model IDs (including the native -n alias), not ambiguous substrings; unknown rates show Unpriced, and partial estimates identify missing prices. There are no hardcoded price guesses in this section. Cached/stale price metadata and incomplete local records remain visible. Empty verified records show zero; failed reads remain unavailable.

Daily usage covers this machine and is not attributed to an account. Failed reads show unavailable data instead of a fabricated zero.

Both interfaces read the existing low-quota coordinator and never create another scheduler. Mac exposes pending cancellation using the original pending ID, and the full Settings UI retains instructions/check actions. The shared panel's detail view preserves pending IDs, source/target, instructions, cancellation and check actions. Backend switching decisions remain authoritative.

## Settings

Menu bar display preferences separately control aggregate scope, account display family, email/note order, visibility of invalid or manually disabled accounts, aggregate visibility, quota windows, reset-time display, icons and color thresholds. Defaults hide unreadable, forbidden and actively validation-blocked accounts; missing/stale quota alone does not hide an account. Above 60% is green, 20–60% inclusive uses a yellow bar and below 20% is red. Visible manually disabled rows retain normal identity/caption styling; their status icon, status label and quota tracks are red. Account rows display usable quota as 0%, without modifying cached observations or including disabled accounts in aggregates. They cannot activate switching. Redundant row/timestamp/coverage tooltips are removed. Reset-time display in Settings offers On hover (default), Always and Hidden, while preserving older hover-on/off preferences: on hover, quota bars narrow to make room for a clock icon and short countdown; the bars remain visible, while percentages, row height and menu width remain fixed. Always keeps the same narrowed bar and countdown visible without hover. Hidden uses the full bar width. Disabled accounts retain 0% and a Disabled caption. Switch controls use AppKit highlight feedback on hover. Account labels do not navigate; switching uses the explicit right-side control. Other unknown data stays neutral; all percentage text uses the normal system foreground independently of bar colors. Displayed percentages round to integers without comparison symbols while calculations keep their original precision. Threshold patches reject invalid ordering and cannot hide both windows. Family selection is available only in Settings; reopening the menu uses the saved selection. Failed Settings saves retain the previous selection and display an error. The root menu has a GitHub action and no redundant About entry. Action rows use SF Symbols and omit ellipses. Model selectors explicitly name Gemini, Claude and GPT, and menu text uses spacing instead of dot separators; labels consistently name the Gemini and Claude/GPT families and retain the mean-remaining metric. Identity preferences use Email first, Note first and Email only.

General Preferences includes OS launch-at-login and macOS Dock visibility controls. Hiding the Dock icon also enables background startup. The menu and reopening the running app can show the main window; closing it returns to the menu bar without a Dock icon. Login registration is queried from the OS and is only changed by an explicit setting, not migration/startup. Development builds cannot register login items.

Desktop and menu-bar preferences use dedicated atomic setters under the ordinary configuration lock. Older ordinary Settings saves preserve the latest dedicated preferences both on disk and in the visible editor, including when their responses arrive after a newer dedicated save. Failed OS writes are compensated and rollback failures remain visible. On macOS the native activation policy is checked, rather than treating successful dispatch as proof that the Dock setting took effect. Opening and closing the main window reconcile the latest in-memory preference, without replaying an old disk snapshot. If the tray fails, background start is suppressed and a regular Dock presence is retained.

Run `node scripts/test-macos-desktop.mjs` in a macOS desktop session for native lifecycle acceptance. It builds a fixture using the production desktop/config code, a temporary configuration and its own status icon. It checks startup, reopening, close after native policy drift, repeated preference changes and tray-unavailable recovery without loading accounts or writing login registration. This is separate from mocked browser acceptance and installed-package verification.

## Verification

Frontend build, 27 existing quota/presentation checks, 12 scoped-aggregation/color checks, 10 settings contract checks, 6 desktop UI race checks, and synthetic-IPC menu browser cases cover the shared layout and data guards. Rust tests additionally cover the actual Mac menu projection: independent windows/families, duplicate/conflicting pools, unknown and expired observations, stale/disabled accounts, known zero, scoped means, separate availability counts, color boundaries, visibility, identity ordering, short reset labels, legacy defaults and rejection of invalid patches without altering the stored file. Synthetic UI tests include 424×640, 380×480 and 320×400, all accounts, inert identity labels, the inter-column gutter, failed reads/refreshes, concurrent activation, preferences, language and material events.

Live quota regression tests use an isolated directory with synthetic current/backup accounts. They cover stale backup observations becoming visible from a subsequent disk snapshot in the existing row order, both aggregate windows updating, and failed/removed/disabled observations clearing usable quota. These projection checks do not establish physical menu tracking or installed-package acceptance.

This round passed the production frontend and Mac arm64 release builds, 121 Rust checks (2 helper cases ignored), 19 menu/Settings browser cases and 14 installed CLI checks. Browser cases cover inert account labels and fixed percentage geometry with hover, always-visible and hidden reset times.

Mac package verification is recorded in the maintainer documentation. Login boot and additional displays still require host-specific acceptance. Native Windows/Linux viewport, console and package results are tracked separately in [native acceptance](maintainers/native-gui-acceptance.md) and the release notes; browser success does not establish them.

## References

The layout references [CodexBar](https://github.com/steipete/CodexBar). AppKit renders the native material rather than a CSS blur. No third-party UI source or assets are copied. The existing pricing cache is populated from [Google Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) and [Google Agent Platform pricing](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing); the menu reads this cache without refreshing prices on open.
